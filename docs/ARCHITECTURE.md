# 架构约定

本文件记录架构方向。首版现已实现，使用 React + TypeScript + Vite；实际目录与约束如下。0.2 增加 uuid 与 hash-wasm，并统一资源限制。

## 运行模型

静态托管提供 HTML、JS、CSS、Worker、Wasm、字体与可选 OCR 模型；浏览器完成计算并让用户下载结果。目标域名为 `vec.im`，正式访问使用 HTTPS，本地开发使用 HTTP localhost。

采用浏览器原生 API → JavaScript 库 → Wasm 引擎的选择顺序。Wasm 用于补充能力，首版不要求人为引入 Wasm。TypeScript 编译为 JavaScript，React 实现 UI，Vite 输出静态文件。PDF.js 搭配同源 Wasm 解码器；pdf-lib 与 Web Crypto 完成本期主要处理。

## 模块边界

实际目录：

```text
src/
  App.tsx               分类、搜索、路由与应用工作区
  i18n.tsx              浏览器语言检测、双语上下文与错误文案
  registry.ts           15 项工具的双语注册信息
  tools/                开发者工具及文档工具操作界面
  engines/              编解码、密码学、PDF 编辑与渲染
  workers/              耗时任务调度及结果协议
  components/           输入、下载、进度与错误组件
scripts/                同源 PDF 资源和依赖声明生成
public/                 图标、静态托管规则及生成资源
tests/                  引擎、组件状态与协议测试；样本在测试中生成
```

当前注册表包含 ID、类别、双语名称/说明、搜索标签与图标；应用按类别懒加载工具组件，界面只呈现已实现工具。离线资源清单随 PWA 阶段加入。PDF 页面操作共用一个引擎适配层，避免各工具重复绑定上游 API。

## 文件和任务生命周期

1. 用户选择或拖入文件，执行类型、大小、页数等适用检查。
2. 只在打开相应工具时加载引擎；把耗时任务交给 Worker。
3. 根据引擎支持程度选择流式/分片处理；不假设 Worker 自动降低内存占用。
4. 任务返回进度、结构化错误和可下载结果；多个文件允许逐项失败。
5. 引擎不能协作取消时终止对应 Worker，并在下次使用时重建。
6. 清空任务时释放 Object URL、画布、Worker 缓冲与文件引用。

浏览器垃圾回收不能保证秘密字节立即从物理内存抹除；产品只承诺清除应用持有的引用及不主动持久化，不宣称安全擦除。

## 输入与密钥

- 默认不持久化输入、原文件、私钥或结果；收藏只保存工具 ID，设置只保存非敏感偏好。
- 输入不出现在 URL、控制台日志、分析埋点、错误上报与远程模型请求中。
- 原始 HTML、Markdown 和 DOCX 导出的 HTML 都需要净化；默认阻止文档触发外链图片请求。
- 使用浏览器密码学随机源；不自行设计加密算法。算法、密钥用途、导出格式和签名格式必须显式。
- 测试夹具使用自造密钥和文档；用户真实文件不加入 Git。

## 文档引擎

- PDF.js：预览、缩略图、页面栅格化与文本层读取。
- pdf-lib：页面组合、图片嵌入与受支持表单等操作；不使用 ignoreEncryption 冒充解密。
- Mammoth：后续 DOCX 语义内容提取，需要额外 HTML 净化。
- OCR：后续评估 Tesseract.js；PDF 先渲染为逐页图像，语言包按需缓存。
- XLSX、PDF 加密/优化、Office 排版与高级编辑：先验证独立引擎，暂不选定实现。

维护状态、资源体积、许可证和浏览器支持在真正引入依赖时再次核查并锁版本。参考资料见 [REFERENCES.md](REFERENCES.md)。

## 静态托管与离线

- 站点路由选择需与静态托管的回退规则匹配，验证直接访问和刷新。
- 自托管生产 Worker/Wasm/字体，使用固定版本；为 `.wasm` 配置 `application/wasm`。
- 引入依赖 SharedArrayBuffer 的多线程引擎时，部署 COOP/COEP 并检查 crossOriginIsolated；首版无此依赖则不强加线程要求。
- PWA 后续实现：壳资源轻量缓存，重型工具由用户按模块下载，展示体积并支持清理。
- 文件不上传不等于首次访问无需联网；离线仅承诺已缓存模块，浏览器存储可能被回收。
- 界面静态资源与引擎资源升级要保持一致，旧缓存失效不应破坏当前任务。

## 当前不引入的结构

不为尚未出现的需求搭建微服务、账户系统或复杂插件执行环境。等到实际出现独立包复用需求再拆工作区；未来媒体和游戏可以沿用工具注册与引擎加载接口。


## 语言状态

启动时读取 `vecspace.language`。有效手动选择（zh/en）优先；否则依次匹配 navigator.languages 中的中文或英文，无匹配时为英文。浏览器拒绝存储时，当前页面仍可切换。

语言状态独立于工具组件和路由，不使用语言路径前缀、查询参数或跳转。切换更新 HTML lang、页面标题、导航、标签、结果周边文案和错误提示；文件字节、输入、结果和当前工具状态保持不变。


## 大文件与选项扩展（0.2）

- `src/limits.ts` 集中管理各类输入和输出的上限，PDF 与普通编解码不再共用大小限制。
- PDF 界面保存原始 File；导入解析时将读取的缓冲区所有权交给 PDF.js。导出时把 File 传给计算 Worker，再按需读取；合并逐个加载源文件。
- PDF 结果通过 transferable ArrayBuffer 返回，避免在 Worker 和主线程之间再次复制输出。
- 哈希引擎使用 hash-wasm 内嵌的 Wasm；每次读取 4 MiB 并增量更新，支持取消。无需远程运行时 CDN。
- 页面缩略图仍按每组 8 页渲染；升高页数上限不会同时渲染全部页面。
- UUID/哈希/签名参数和其他选项仅保存在当前组件状态，语言切换继续保留这些状态。
