# 实施路线

所有条目为待实现计划，优先级不代表已实现状态。首版共 15 个功能项：8 个开发者工具、7 个文档工具；页面整理中的多个操作共用一个工作区。

## M0：应用基础

- 建立前端应用与静态构建，确定框架、包管理器和依赖锁文件。
- 建立工具注册表、两类导航、搜索、工具页和无障碍基础样式。
- 建立文本输入/结果面板、文件选择/拖放、下载与错误提示组件。
- 建立 Worker 任务协议：启动、进度、结果、失败、取消、释放资源。
- 从一开始采用同源引擎资源与字体，不依赖第三方运行时 CDN。
- 验收：静态产物可在 HTTP 本地预览；工具深层链接刷新可用；不依赖业务后端。

## M1：开发者工具首版

- DEV-001 ～ DEV-008：Base64、URL 编解码、JSON、UUID v4、时间戳、SHA 摘要、密钥生成、签名与验签。
- 先完成编解码和 JSON，再接入密钥与签名的导入导出约定。
- 密钥首版明确为 RSA-PSS 和 ECDSA P-256；测试与浏览器之外的已知实现互操作。
- 验收：Unicode/非法输入/大整数/时间单位覆盖；摘要与签名采用公开测试向量及外部夹具；错误密钥、错误签名和篡改内容必须验证失败。

## M2：文档工具首版

- DOC-001 ～ DOC-006：PDF 预览、合并、拆分提取、页面整理、图片转 PDF、PDF 转图片。
- DOC-018：文本整理，作为非 PDF 文档工具的第一项。
- PDF 工具复用缩略图、页码范围选择、文件顺序和导出面板。
- 验收：重排/旋转/混合页尺寸/中文/图片方向正确；加密或损坏输入有清楚错误；取消后能继续新任务；导出文件能重新打开且页数、顺序正确。
- 用代表性样本人工检查导出渲染；原件保持不变；多结果下载无文件名碰撞。

## M3：首版质量与静态发布准备

- 验证 Chrome、Firefox、Safari 的桌面主流程与移动端基本操作；记录具体测试版本。
- 用代表性文件测量时间、峰值内存与可取消性，据结果设限制，不承诺通用最大文件大小。
- 检查初始化资源加载完成后，用户输入、文件字节和密钥不触发外发请求。
- 验证路由回退、Worker/Wasm 资源 MIME、缓存版本与部署响应头。
- 到这里产出首版静态站点构建；`vec.im` 的实际部署是独立交付动作。

## M4：常用扩展与离线

- 开发者工具：JWT/HMAC、密钥格式、随机密码、正则、数据格式转换、进制等 P1 功能。
- 文档工具：PDF 文本提取、水印/页码/表单、文本比较、Markdown、DOCX 内容提取、CSV/XLSX 数据转换。
- 加入 PWA、按模块离线下载、收藏、缓存管理和批处理。
- 验收：首次联网下载所需模块后断网复测对应功能；缓存缺失或被浏览器清理时给出明确状态。

## M5：专项验证

每个 P2 功能先做独立技术样例，提交输入/输出样本、性能记录、兼容性与依赖许可说明，再决定是否产品化。优先顺序建议为 OCR → PDF 体积优化/密码 → 高级文档转换。

## 完成标准

功能清单、工具实际状态和界面入口保持一致；尚未实现的能力不能以可用按钮出现。测试聚焦数据正确性、格式互操作、输入失败路径和真实文件处理，不给纯文案变更补镜像测试。
